Open your mobile app repository in an AI coding agent and paste the prompt below. The agent installs Visor locally, adds the Visor skill to the repository, connects to a running app, and builds the first semantic map.

```text
Set up Visor in this mobile app repository and complete the initial agent-driven discovery phase. Do the work instead of only giving me instructions.

Work from the repository root, preserve existing changes, and use the existing package manager when possible.

1. Verify Node.js 20 or later. If this repository already has a Node package manifest, install `visor-ai@latest` as a local development dependency with its package manager. Otherwise install it into an isolated ignored runtime with `npm install --prefix .visor/runtime visor-ai@latest`. Use the resulting local `visor` binary for every command; do not depend on a global installation.
2. Install the Visor repository skill for the current agent and other agents that share the canonical project skill directory:
   `npx --yes skills@latest add AleksKapera/visor --skill visor-discovery --copy --yes`
   Verify that `.agents/skills/visor-discovery/SKILL.md` and `skills-lock.json` exist. Read that SKILL.md completely now and follow it for the rest of this task.
3. Add `.visor/` to `.gitignore` if it is not already ignored. Keep the installed skill and `skills-lock.json` as repository files, but keep maps and runtime artifacts local.
4. Inspect the project and local machine to determine whether this run targets iOS or Android. Check installed Appium drivers with the local Appium CLI and install the required `xcuitest` or `uiautomator2` driver if it is missing. Do not replace a working compatible driver unnecessarily.
5. Find or boot exactly one simulator, emulator, or connected device. Determine the installed app's real bundle id or package id from the project and device. Build or install the app using this repository's normal workflow if needed. Ask me only if the target, app id, authentication state, or a required manual choice cannot be determined safely.
6. Use `.visor/maps` as the persistent map directory. If it already contains a map, preserve and reuse it; do not delete it. If it is new, confirm that discovery starts without prior map knowledge.
7. Start Visor, keep the daemon and app session warm, and use explicit `--device`, `--app-id`, `--attach`, and `--map-dir .visor/maps` values on runtime commands.
8. Run `visor discover`. Use compact `data.memory` and the exact `data.observation_token` to annotate the current screen without another device read. Then explore safe, high-value navigation one action at a time, annotating each stable screen immediately.
9. Discover global navigation, reliable back or close behavior, and one representative nested route per major hub. Do not run generic `discover --crawl`. Do not execute actions classified `risky`, `needs-input`, or `unknown`. Use screenshots or UI source only when compact memory is genuinely ambiguous.
10. Verify at least one known multi-step or alternate path with a single deterministic `visor route` request. If an unknown state appears, use `needs_discovery`, annotate its exact token, add a safe recovery path, and retry gracefully.
11. Leave the app on a stable known screen and keep the daemon available for the next agent task. Finish only after reporting: the device and app id, installed skill path, map and agent-memory paths, semantic screens and routes learned, route timing/outcomes, unresolved gaps, and risky or input-dependent actions you intentionally did not execute.

Do not commit or publish changes unless I ask. Tell me which setup files should be committed so future agents inherit the Visor skill.
```

## What the prompt adds

The setup keeps two kinds of state in your repository:

- `.agents/skills/visor-discovery/` and `skills-lock.json` are shareable agent instructions. Commit them with your project.
- `.visor/` contains private local maps, checkpoints, and runtime state. Keep it ignored and do not commit it.

On later tasks, ask your agent to use Visor normally. The installed skill tells it to read compact agent memory first, execute known multi-step navigation as one deterministic route, and rediscover only when the live app reaches an unknown state.

<Warning>
The initial discovery phase requires a bootable Appium environment, an installed app, and any required test account. The agent should stop for manual input instead of guessing credentials, permissions, or consequential actions.
</Warning>
